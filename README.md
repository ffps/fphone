# <p align="center"><img src="art/icon.png" /><br />Кукуха — персональная система видеосвязи</p>

**Кукуха** — приложение для голосовых и видеозвонков между пользователями собственного сервера. Проект состоит из Android-клиента, браузерного PWA и серверной части на Go.

## Первая версия для тестовой эксплуатации

Текущий выпуск — **1.0.0**. Это первая версия «Кукухи» для тестовой эксплуатации, а не завершение развития проекта.

В состав входят Android-клиент (минимум Android 8.0), браузерный PWA и сервер на Go с SQLite, WebSocket, WebRTC/TURN и push-интеграциями. Серверный компонент в выпуске 1.0.0 не менялся относительно серверной версии 0.4.3.

В выпуске собраны голосовые и видеозвонки Android ↔ Android и Android ↔ PWA, приём вызовов через FCM и Web Push, подтверждение получения входящего вызова, определение занятости обычной мобильной линии, обмен сообщениями с подтверждением доставки на каждое устройство, локальная история вызовов, управление камерой, микрофоном и громкой связью. Иконки Android и PWA обновлены с утверждённым жёлто-зелёным градиентом № 2; силуэт птицы сохранён.

### Известные ограничения

- На отдельных Samsung Galaxy S23 с Android 17 в Samsung Internet может зависать локальное превью камеры PWA; исходящее видео при этом продолжает передаваться собеседнику. Требует дополнительного тестирования.
- Поведение фоновых push-уведомлений зависит от браузера, ОС и настроек энергосбережения устройства.

### Рекомендации по установке и обновлению

- Android: устанавливайте APK из GitHub Release. Для обновления сохраняйте прежнюю подпись приложения.
- Сервер: обновление серверного бинарного файла для версии 1.0.0 не требуется.
- PWA: обновите статические файлы каталога `pwa/` на сервере; версия кеша Service Worker увеличена.
- Перед тестовой эксплуатацией рекомендуется сохранить резервную копию конфигурации и базы данных сервера.

## Возможности

- Видеозвонки между Android-устройствами и браузерами.
- Передача медиа через TURN-релей собственного сервера. Это помогает устанавливать соединения между телефонами за мобильным NAT/CGNAT.
- Входящие вызовы в Android через Firebase Cloud Messaging (FCM).
- Входящие вызовы в браузерном PWA через стандартный Web Push.
- Контакты, аватары и отображаемые имена пользователей.
- Отправка текстовых сообщений контактам на Android и в поддерживаемые PWA-клиенты.
- Определение занятости обычной мобильной линии Android и короткие гудки занятости у вызывающего клиента.
- Подтверждение получения входящего вызова: гудки контроля посылки вызова начинаются после подтверждения вызываемого устройства.
- Управление камерой, микрофоном и громкой связью; переключение фронтальной и задней камер.
- Подтверждение фактической доставки сообщений на устройства; отправитель получает отдельное уведомление для каждого доставившего сообщение устройства.
- Локальная история вызовов на каждом устройстве. История Android и PWA не синхронизируется между собой; сервер не хранит историю звонков.
- Диагностический журнал клиента и серверные журналы.

Подробная документация по установке, настройке и обслуживанию серверной части находится в **[server/](server/README.md)**.

## Android-клиент

- Минимальная версия: **Android 8.0 (API 26)**.
- Вход выполняется по адресу сервера, логину и паролю, которые создаёт администратор. Для работы требуется сервер с белым IP адресом.
- Для звонков необходимы разрешения на микрофон и камеру; для надёжного приёма вызовов — уведомления и разрешение на полноэкранные уведомления (на поддерживаемых версиях Android).
- На некоторых устройствах нужно снять ограничения фоновой работы и энергосбережения для приложения.
- Контакты и порядок их отображения хранятся на устройстве.
- История звонков хранится локально на телефоне.
- При выходе из аккаунта клиент отправляет запрос серверу, после чего запись устройства удаляется из серверного списка устройств.

### Сборка Android

Для локальной сборки нужны JDK 17, Android SDK и Gradle 8.7.

1. Получите `google-services.json` в Firebase Console и положите его в каталог `app/`.
2. Выполните сборку:

```bash
gradle assembleDebug -PfphoneAppId=<application_id>
```

`application_id` должен соответствовать приложению, зарегистрированному в Firebase. Файл `google-services.json` не следует добавлять в публичный репозиторий.

### Сборка релизов через GitHub Actions

Workflow собирает релиз при отправке тега `vX.Y.Z` либо коммита в `main` с сообщением, содержащим `[release vX.Y.Z]`.

Для подписанной сборки в Secrets репозитория задаются:

- `KEYSTORE_BASE64` — keystore в Base64;
- `KEYSTORE_PASSWORD` — пароль keystore;
- `KEY_ALIAS` — alias ключа;
- `KEY_PASSWORD` — пароль ключа;
- `GOOGLE_SERVICES_JSON_BASE64` — `google-services.json` в Base64.

APK публикуется в GitHub Release под именем `Kukukha-X.Y.Z.apk`. Для всех обновлений необходимо использовать тот же ключ подписи.

## Браузерный клиент (PWA)

PWA находится в `pwa/` и раздаётся сервером из `data_dir/web/pwa/` после копирования файлов при развёртывании.

- Для фоновых уведомлений пользователь должен войти в PWA и включить уведомления в настройках.
- Для Web Push серверу нужны VAPID-ключи (см. `server/README.md`).
- История звонков PWA хранится в `localStorage` конкретного браузера и не синхронизируется с Android или другими браузерами.
- Если браузер или его процесс полностью завершён, возможность доставки push зависит от браузера, ОС и настроек фоновой работы.

## Как устроены звонки

1. Клиенты авторизуются на сервере.
2. Сигнализация вызова и события состояния передаются через WebSocket.
3. Медиа передаётся по WebRTC. В штатной конфигурации ICE policy `relay` направляет медиатрафик через TURN-релей сервера.
4. Если клиент недоступен по WebSocket, сервер пытается разбудить его push-уведомлением: FCM для Android или Web Push для PWA.
5. После открытия приложения клиент восстанавливает соединение и обрабатывает вызов.

Сервер не хранит историю вызовов.
В SQLite находятся учётные записи, сессии, устройства и данные, необходимые для работы сервиса. Подробности приведены в [документации сервера](server/README.md).
